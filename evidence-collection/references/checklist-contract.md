# 五维清单逐行调查契约

## Run-first最高规则

正式用户报告前必须先通过`run_case.py`编译并执行61项动作队列。只要仍有`READY`、`RUNNING`或可重试动作，禁止将缺行自动写成“未执行”后交付。`BLOCKED`、`ERROR`、`PARTIAL_VERIFIED`和`NEEDS_HUMAN`不得因为已有一条结果记录而从待办消失。只有队列达到`QUIESCENT`，或用户明确要求部分输出，才允许渲染报告。

用户默认报告为单表五列：编号/优先级、证据事项与核查要点、平台/网站、结果与附图、下一步重点。每行最多两张小图，图片必须在结果列内；不得以逐行截图附录再次展开全部任务。canonical保真清单继续作为审计底稿保存，两类输出不得混用。

## 目标

用户输入权利人和疑似侵权链接后，AI以用户当前DOCX清单为任务源，逐行调查并输出“部分填充清单”。“部分填充”指全部行都有执行记录，但只有真实找到且可核验的事实才填写为结果；未找到、受阻、需人工和不适用也必须留痕。

## 权威顺序

1. 用户本次提供的DOCX。
2. Skill内置的用户修改版DOCX。
3. evidence-matrix.json和其他参考文件。

下级资料不能删除、改写或跳过上级清单内容。

## 调查对象路由（最高优先级）

1. 除2-3-1至2-3-5知名度项目外，全部任务默认且必须从被告商品、被告品牌、型号/SKU、店铺/账号、页面展示销售主体、经营主体、生产商/备案人或其关联主体种子出发。
2. 只有2-3-1至2-3-5可以使用 `PLAINTIFF_REPUTATION` 独立检索原告或权利人产品。其他任务不得把原告产品、原告官网、原告官方店铺或原告宣传材料作为默认搜索对象。
3. 权利基础可以使用 `RIGHTS_BASIS` 查询注册号、权利人、权利状态、授权链及官方权利数据库，但原告产品页面不得替代被告任务。
4. 比较任务使用 `COMPARISON` 前，必须已有对应的 `DEFENDANT` 动作和被告侧原始材料。原告材料只能作为固定比较材料，不能独立支持该行完成。
5. 行业、统计、裁判或监管查询可标 `NEUTRAL`，测购、公证、专家、问卷、披露或法院调取可标 `MANUAL`；两者仍须通过 `seed_refs` 指向具体被告商品、主体、地区或本案对象。
6. 禁止反向替代：找不到、打不开或尚未提取被告商品时，应标BLOCKED、NOT_FOUND或NEEDS_HUMAN，不得转而检索原告产品并将原告事实写入被告任务。

## 被告种子闸门

打开疑似侵权链接后，先建立 `defendant_seed`，至少提取一个可核验的被告侧种子，并优先提取被诉商品完整标题。种子字段包括商品完整名、规范化短名、被诉品牌、型号/SKU、店铺/账号、平台展示销售主体、证照经营主体、生产商/备案人、平台商品ID、原始及最终URL、提取时间和来源引用。

商品名称尚未提取时，应先完成平台登录或验证码协作并重试。仍无法取得时，依赖被告种子的任务不得开始，也不得使用权利人信息补位。除2-3-1至2-3-5外，每个有实际联网动作的任务至少包含一条 `subject_role=DEFENDANT` 的动作。

## 行级状态

| 状态 | 含义 | 可否写事实 |
|---|---|---|
| COMPLETE_VERIFIED | 该行关注点已有直接、完整且可核验材料 | 可以，只写来源直接支持的范围 |
| PARTIAL_VERIFIED | 只找到部分事实 | 可以，必须同时列未找到部分 |
| LEAD_ONLY | 只有搜索摘要、评论、第三方转述或单一弱线索 | 不可写成已证实事实 |
| NOT_FOUND | 完成已记录范围的检索但未发现可核验材料 | 不可 |
| BLOCKED | 登录、验证码、失效、付费墙或技术限制 | 不可 |
| NEEDS_HUMAN | 测购、公证、平台披露、法院调查令、专家、问卷等 | 不可假装已完成 |
| NOT_APPLICABLE | 与本案权利类型、主体或行为确实无关 | 不可；必须逐行说明理由 |
| CONFLICT | 真实来源之间存在冲突 | 只并列冲突，不代替律师裁断 |
| ERROR | 工具或程序异常 | 不可写成未找到 |

## 来源等级

| 等级 | 典型来源 | 使用边界 |
|---|---|---|
| A | 官方登记、官方监管、官方裁判、用户原件 | 可直接支持其载明事实 |
| B | 被调查主体官网、年报、招股书、平台原页面 | 可写“主体自述/平台展示”，不能扩大 |
| C | 权威新闻、行业报告、第三方数据库 | 至少两个独立发布主体相互印证后才能支持已核验事实 |
| D | 搜索摘要、评论、自媒体转述、AI评价 | 仅作线索 |

置信判断不等于诉讼证据能力。公开抓取仍是PUBLIC_CAPTURE，除非另有公证、可信时间戳或法院认可的固定材料。

## 每行必须记录

- 原任务编号及模板定位。
- 本行 `required_subjects` 及每条动作的 `subject_role`。
- 每条动作实际使用的 `seed_refs`，并能追溯到 `defendant_seed`、权利基础或知名度白名单材料。
- 每个平台是否实际查看。
- 查询式、URL、平台、访问时间和结果。
- 找到的事实及其来源ID。
- 来源标题、发布主体、URL或真实文件、访问/取得时间、来源等级。
- 事实能证明什么、不能证明什么。
- 未找到内容、受阻原因、人工下一步。

## 方框规则

- √：该平台已实际打开或执行检索，无论结果是找到还是未找到。
- ×：未执行、无法访问、无入口或不适用。
- 方框不是事实结论，具体结果必须看新增AI列。
- 原平台名称和顺序不得改动。

## 禁止编造规则

1. finding没有来源ID时拒绝登记。
2. 来源不存在、URL无效、访问时间缺失或证据文件不存在时拒绝登记。
3. 搜索摘要不得写成页面正文事实。
4. 只看到宣传用语时必须标明“主体自述”。
5. 总营收、总产能、总销量不得直接等同涉案产品数据。
6. 中标不得直接等同实际交付。
7. 平台展示销量需披露刷单和口径风险。
8. 未发现不得改写为事实不存在。
9. 工具错误不得改写为未找到。
10. 任何金额、主体关系、权利状态和裁判结论都不得凭模型记忆补齐。
11. 非2-3-1至2-3-5项目不得以 `PLAINTIFF_REPUTATION` 或原告产品作为唯一或首要检索对象。
12. 被告向任务没有DEFENDANT动作时，不得登记为COMPLETE_VERIFIED、PARTIAL_VERIFIED、LEAD_ONLY或NOT_FOUND。
13. COMPARISON动作前没有对应DEFENDANT动作，或原告材料未与被告对象一一对应时，不得登记比较结论。
14. 权利基础材料只能证明权属、状态或授权链，不得据此填充被告主体、渠道、规模、销量、利润或恶意事实。

## 模板保真

- 原模板复制到input/original_checklist.docx并记录SHA-256。
- 输出DOCX仅允许修改word/document.xml。
- 非任务表内容必须逐字不变。
- 任务表的前四列必须逐字不变。
- 第五列只允许替换方框字符，平台文字必须不变。
- 每行末尾追加一个新单元格；不得删除、排序、拆分或合并原行。
- 所有其他OOXML包部件逐字节保留。
- 所有改动写入change_ledger.json。

## NOT_FOUND固定语义

“截至【时间】，在【检索范围】内未找到可核验公开材料。本结论仅表示本次公开检索未发现，不代表该事实不存在。”

## 交付门槛

- 所有任务都有行级结果。
- 所有平台都有√或×及原因。
- 所有已核验事实都有真实来源。
- 所有动作都有合法的 `subject_role` 和非空 `seed_refs`。
- 除2-3-1至2-3-5外，所有已执行任务均从被告种子出发；比较行通过在先被告动作校验。
- 原模板和原内容通过保真校验。
- 输出DOCX完成结构校验和可用的视觉渲染检查。
