# 联网调查与取证状态机

## Run-first调度门禁

按W0种子、W1商品渠道、W2主体、W3官方数据库、W4派生比较、W5登录/人工的顺序调度。一个动作遇到登录、技术错误或人工依赖时，只park该动作并继续其他READY动作。所有READY动作耗尽后才进入WAITING_LOGIN、WAITING_MANUAL或QUIESCENT。主代理必须循环调用真实Browser、企查查MCP、搜索和官方数据库，再把真实结果commit回队列；本地脚本不得生成伪联网结论。

## 一、被告种子闸门

直接访问疑似侵权URL，并在登录态可见页面中逐字提取以下被告侧种子：

1. 被诉商品完整标题和规范化商品短名。
2. 被诉品牌、型号、SKU、规格及页面商品ID。
3. 店铺或账号名称、店铺ID、账号ID及认证信息。
4. 页面展示销售主体、店铺证照经营主体、收款或开票主体。
5. 生产商、委托方、备案人、注册人及包装可见地址、电话。
6. 平台、原始URL、最终URL、提取时间和对应页面证据。

以上字段写入 `defendant_seed`，每个字段保留来源引用。除第2-3-1至2-3-5项知名度调查外，任何联网调查开始前必须至少取得一个可核验的被告侧种子。商品名称未提取时，先完成平台登录或验证码协作并重试；仍无法取得则将依赖该种子的任务记为BLOCKED，不得改搜权利人或原告产品补位。

## 二、调查对象路由

- `DEFENDANT`：默认角色。以被诉商品、被诉品牌、SKU/型号、店铺、销售主体、生产/备案主体及关联主体为对象。
- `PLAINTIFF_REPUTATION`：仅允许用于2-3-1至2-3-5。只有这五项可以独立检索原告或权利人产品、品牌、销量、宣传、报道、评价和排名。
- `RIGHTS_BASIS`：只用于注册号、权利人名称、权利状态、授权链及官方权利数据库查询。原告产品页面不能替代任何被告任务。
- `COMPARISON`：必须先有对应的DEFENDANT动作和被告侧原始材料；原告材料仅作为固定比较材料，不得单独完成该行。
- `NEUTRAL`：行业、统计、裁判或监管等中立来源；仍须通过 `seed_refs` 说明与被告商品、主体、地区或本案对象的关系。
- `MANUAL`：测购、公证、专家、问卷、披露或法院调取；仍须指向具体被告种子和操作对象。

除知名度白名单外，不得以权利人名称、原告商品、原告官网或原告官方店铺作为唯一查询词。不得用原告事实填充被告的主体、渠道、规模、地域、销量、利润、贡献率、故意、明知、参照或特殊因素任务。

## 三、顺序

1. 固定疑似侵权URL并建立 `defendant_seed`。
2. 依次用“被诉商品完整名”“规范化商品短名”“被诉品牌+型号/SKU”“店铺/账号”“销售主体”“生产/备案主体”“地址/电话”“图片特征”精确扩展。
3. 查被告店铺资质、被告官方站和账号、监管/登记机关、法院/政府及交易所公告。
4. 查与被告商品或主体对应的订单/付款/物流链、招投标、备案许可、专利申请及海关记录。
5. 查被告商品的跨平台渠道、地域、销量、产能、利润、贡献率、故意、明知和关联案。
6. 仅在2-3-1至2-3-5中独立调查原告知名度；权利基础只查权利登记及授权链。
7. 对每个缺口给出下一步、负责人、是否需登录、公证、购买或调取。

## 四、来源层级

- A级：官方登记、监管机关、法院、交易所、政府采购/招投标、海关、权利人原件。
- B级：平台主体资质、订单支付物流、经公证/可信时间戳固定的网页、被调查方自认。
- C级：主流媒体、行业报告、券商研报、论文、展会名录。
- D级：第三方工商/权利数据库、搜索摘要、消费者评论、AI评价。只作线索或辅助。

权利状态、主体状态、裁判结果优先用A级来源在访问当日核验。

## 五、受阻降级

依次尝试：

1. 公开直开或安全 capture。
2. 精确搜索页面标题、URL、被诉商品名、被诉品牌、店铺名、型号及缓存摘要。
3. 平台公开网页版、移动版、公开分享页、官方数据库。
4. 用户已有登录态的可见浏览器；用户亲自完成验证。
5. 登录后重新提取 `defendant_seed`；仍受阻则输出App/小程序公证、测购、平台披露或法院调取任务。

不得绕过密码、验证码、短信、人脸、设备绑定、付费墙或反爬措施。每次失败写入 access_log.jsonl。受阻降级不得转为独立检索原告产品。

## 六、搜索矩阵

### 权利基础

- "权利人全称" 商标 注册号
- site:cnipa.gov.cn "权利人全称"
- "权利人全称" 作品登记 著作权
- "权利人全称" 专利
- 权利人官网、招股书、年报、许可/授权链、历史名称与关联主体

以上查询的角色为 `RIGHTS_BASIS`，只证明权利登记、状态和授权链。权利人商品页、官方店铺或宣传页不得被用来完成被告任务。

### 被诉主体和生产者

- "店铺名/账号/品牌" 营业执照
- "电话"、"发货地址"、"收款主体"、"发票抬头"
- "型号" 备案 3C 医疗器械 注册 许可证
- "主体名" 展会 招聘 环评 招投标 专利 海关
- "主体名" 厂家 生产基地 研发 自有工厂

上述“店铺名/账号/品牌”“型号”和“主体名”均指 `defendant_seed` 中的被告侧字段。自称“厂家”只是自认线索；登记注册人、委托方和实际生产厂必须区分。

### 渠道、地域、规模和销量

- 站内搜索及抖音、快手、视频号、小红书
- 大众点评、美团、携程、艺龙
- 电商平台、政府采购、招投标
- 共享、租赁、加盟、连锁、经销商、门店

### 小红书与微博：MCP发现、浏览器核验

1. 小红书只调用只读逻辑工具`xiaohongshu`，微博只调用只读逻辑工具`weibo`。MCP仅执行搜索和候选发现，禁止任何写操作。
2. 每个候选必须由`chrome-devtools`打开并核对规范账号页、笔记页或帖子页；保存浏览器最终URL、页面标题/账号/内容ID、访问时间和AI截图。
3. Chrome不可用时，只有无需登录的公开页面可使用`playwright`核验和截图。Playwright不得复制Chrome认证材料，不得用于已登录页面。
4. 遇到登录门槛时，先尝试使用当前受控Chrome会话的已登录状态（同站点Cookie/自动填充/会话保留）；仍需认证时再在当前会话展示二维码，请用户自行扫码；用户无需且不得发送截图、二维码图片、密码、验证码、Cookie或浏览器存储。
5. `xiaohongshu.com/search_result`、`s.weibo.com`、通用搜索结果、短链、分享中转页和未打开的MCP候选URL均不是规范来源页。
6. 禁止AgentKey及其任何后端。平台MCP不可用时记为运行失败/可重试，不得改用AgentKey或通用搜索伪装完成。
- 环评投资/产线/设计产能、政府批文、招股书/年报、行业报告
- 国内注册地/销售区域/发货地；中国出口和外国进口记录

本节全部以被告商品、被告品牌、被告店铺或被告主体为种子，不得以原告产品的官方渠道、销量或门店替代。

### 利润率

- 被告年报、招股书和财务披露优先。
- 无被告数据时，查与被告商品同品类、同渠道、同规模的无关联企业及行业/券商报告。
- 原告年报或原告产品利润不得作为默认替代；确需比较时必须标 `COMPARISON` 并先完成被告动作。

### 贡献率

- 从被告商品及其页面宣传、销量、价格、转化、评论、奖项、许可和技术表述出发。
- 专家、问卷、AI评价、论文及横纵向比较必须明确被告商品输入和样本。
- 需要原告权利材料比较时标 `COMPARISON`；先固定被告材料，原告材料仅作成对比较。

### 原告知名度白名单

- 仅2-3-1至2-3-5可独立检索原告品牌、原告商品和涉案权利。
- 检索广告合同/发票、代言、专项审计、消费者评价、新闻、销量、门店/用户覆盖、排名和评奖。
- 3-1-3只能复用本节已取得的知名度证据，并另查被告经营地域、行业、期间、渠道和接触机会；不得再次泛搜原告产品。

### 故意、明知、参照与特殊因素

- 专利标识、多权利叠加、历史侵权、以侵权为业、商标囤积
- 代理/劳动关系、诉讼/和解、行政查处、警告函、仿冒商标申请
- 同一权利关联裁判及获赔、律师费、公证费、测购费
- 地区经济、经营/财产、关联公司、失信信息
- 残疾、年龄、精神状态属于敏感个人信息，只在确有合法必要时处理

本节从被告商品、店铺、主体、关联人或行为地种子出发。同一权利裁判等比较材料必须与被告对象成对查询，不能只搜原告品牌案件。

## 七、停止条件

一个方向可标“已完成”仅当：

- 有至少一项A级或B级直接材料，或两项相互独立材料形成强推定；
- 来源、访问时间、文件、哈希、证明目的和局限均已记录；
- 反向证据和口径冲突已说明；
- 仍需公证、购买、登录、平台披露或法院调取的步骤已转人工作业单。
- 每条动作均记录 `subject_role` 和 `seed_refs`；非知名度白名单至少有一条DEFENDANT动作。
- 比较行已有在先DEFENDANT动作，且原告材料仅作为比较材料。

“未找到”必须同时写明检索式、来源范围和日期，不能解释为事实不存在。
